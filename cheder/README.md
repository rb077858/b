### מאגר משותף
- תורנויות (מהודעת המדריך) ושינויים בלו"ז (חופשה, טיול, העברת יום שטיפה...) שאחראי חדר מזין - **מתעדכנים אצל כל החדרים**.
- חדר יכול **להזין אחרת רק לעצמו**: תורנות של החדר גוברת על המשותפת מאותו תאריך ועד העדכון המשותף הבא; שינוי משותף אפשר לסמן "לא חל עלינו".
- **מצב עצמאי:** חדר יכול לצאת מהמאגר המשותף ולנהל הכל לבד (תורנויות, שינויים, ימי ניקיון ויום שטיפה). אפשר לחזור בכל רגע.
- **הגדרות משותפות** (ימי ניקיון, יום שטיפה, "מחוץ לפנימייה") - רק המנהל משנה. כל אחד יכול **לשלוח הצעה** (לשונית "עוד"), והמנהל מאשר בלחיצה בלשונית "הצעות" - וההגדרה מתעדכנת לכולם.

## מבנה הנתונים (Firestore, אוספים `ch_*`)
- `ch_members/{מייל}` - מי מורשה, באיזה חדר, ו-`role`: `manager` (האדמין צירף) או `resident` (הצטרף בקישור, עם `rid` = הדייר שלו).
- `ch_invites/{token}` - קישורים אישיים. האחראי יוצר; ההצטרפות יוצרת את החבר ומסמנת את הקישור כמנוצל באותה כתיבה.
- `ch_rooms/{חדר}` - דיירים, שינויים של החדר, `independent`, `ownSettings`, `ignoredEvents`. רק האחראי כותב, כל החדר קורא.
  - `days/{YYYY-MM-DD}` - החלוקה של כל יום (`assign`, `byPerson`) ומה בוצע (`done`). דייר מסמן רק את שלו.
  - `absences/{id}` - היעדרויות. דייר מסמן רק את עצמו.
  - `duties/{YYYY-MM-DD}` - תורנות שהחדר הזין רק לעצמו.
- `ch_duties/{YYYY-MM-DD}` - תורנויות משותפות. אחראי חדר כותב, רק אדמין מוחק.
- `ch_events/{id}` - שינויים משותפים בלו"ז. מי שהוסיף (או אדמין) מוחק.
- `ch_suggestions/{id}` - הצעות שינוי למנהל.
- `sites/cheder` - הגדרות (ימים פעילים, יום שטיפה). קריאה ציבורית, כתיבה לאדמין.

## הפעלה
1. **פריסת החוקים** (מתיקיית המאגר): `npx firebase-tools deploy --only firestore:rules`
2. כניסה ל-`/cheder/admin/`, צירוף אחראי לכל חדר (וגם את עצמך). כל אחראי שולח קישורים אישיים לדיירים שלו.


## בדיקות
- לוגיקה: `node cheder/test/core.test.mjs`
- חוקי Firestore (אמולטור, דורש Java): `cd firebase/rules-test && npm install --legacy-peer-deps && npm test`
- בדיקה מקומית של האתר מול אמולטורים: פותחים `http://localhost:<port>/cheder/?emu` (לא פעיל באתר האמיתי).
